# ТЗ для агента: Stardew Valley Progress Tracker

**Версия проекта на момент передачи:** v0.1.0 (рабочая, проверена на синтетических сейвах).
**Что от тебя нужно:** превратить эту папку в нормальный GitHub-репозиторий и продолжить разработку по бэклогу.
Читай документ целиком перед первым коммитом — здесь есть проверенные факты о формате сейва,
которые сэкономят тебе часы.

---

## 1. Продукт и пользователь

Локальный трекер прогресса в Stardew Valley для одного игрока (Windows, Steam, игра 1.6.x).
Читает файл сохранения игры, показывает в браузере, что сделано и что осталось: коллекции,
музей, рыба, отправка, готовка, крафт, люди (сердца/ДР/подарки), бандлы Community Center,
плюс свои цели и задачи с автоподсчётом прогресса.

Задача продукта: **убрать необходимость держать прогресс в голове и лазить на вики**.

Ключевые свойства, которые нельзя терять:

1. **Без модов и без SMAPI.** Только чтение файла сохранения.
2. **Без зависимостей.** Только стандартная библиотека Python 3.9+. Никаких `pip install`.
3. **Приватность.** Никаких сетевых запросов: всё локально. Ссылки на вики — обычные `<a href>`,
   клиент их открывает сам, приложение ничего не запрашивает.
4. **Двуязычность.** Названия предметов RU + EN (переключатель приоритета в шапке), подписи
   интерфейса переключаются RU/EN.
5. **Автообновление.** Трекер следит за mtime файла сейва и перерисовывает страницу сам.

Пользователь играет по-русски, поэтому русские названия должны совпадать с игрой
(они берутся из официальной локализации, см. §6).

## 4. Архитектура

```
tracker.py              # CLI: serve | build | info | open
  ├─ find_saves()       # поиск сейвов (Windows/macOS/Linux/Proton) + --save/--saves-dir
  ├─ parse_save()       # XML -> плоский dict (независимо от namespace)
  ├─ build_state()      # dict + data/*.json -> состояние для фронтенда
  ├─ render()           # шаблон + встроенный JSON  -> HTML
  └─ Handler/serve()    # stdlib http.server: GET /, /api/state, /api/refresh, POST /api/goals
build_data.py           # сборка data/ из распакованного Content игры (запускается редко)
assets/dashboard.html   # весь фронтенд: inline CSS + JS, рендер из window.__STATE__
data/*.json             # справочники (см. §9)
tests/                  # unittest + генератор синтетического сейва
goals.json              # пользовательские цели/задачи (в .gitignore)
```

Поток данных: **сейв → parse_save → build_state (+ data/*.json) → JSON → dashboard.html (JS-рендер)**.
Фронтенд не содержит бизнес-логики подсчёта: всё считается в Python, JS только рисует.
Живое обновление: поток в `serve` следит за mtime, `build_state` пересобирается, страница раз в 3 с
дергает `/api/state` и, если `meta.save_mtime` изменился, перерисовывается (сохраняя scroll).

Состояние (`/api/state`) — ключи: `meta, counts, fish, museum, shipped, cooking, crafting, people,
bundles, alerts, goals`. `counts[key] = [сделано, всего]`. Полные формы смотри в `build_state()`;
при добавлении полей — только добавлять, не переименовывать существующие (фронтенд и тесты на них завязаны).

## 5. Проверенные факты о формате сейва (НЕ перепроверяй с нуля)

Файл: `%APPDATA%\StardewValley\Saves\<Ферма>_<ID>\<Ферма>_<ID>` — XML без расширения, рядом `SaveGameInfo`.
Корень `<SaveGame>`, атрибуты с `xsi:type` (`xmlns:xsi=...`). Часть сейвов 1.6 использует префикс `p3:` —
поэтому в коде все обращения идут через локальные имена тегов (`ln()`), не через `findall("tag")`.

| Что | Где в сейве | Формат |
|---|---|---|
| Фермер | `SaveGame > player` | элементы; мультиплеер — несколько `player` (**берём host = первый**) |
| Имя/ферма/деньги | `player > name / farmName / money` | строки/число |
| Дата | `player > dayOfMonth / currentSeason / year` (фолбэк — поиск по всему документу) | `fall`, 12, 3 |
| Время | `player > timeOfDay` | 1350 = 13:50, 2600 = 2:00 |
| Рыба | `player > fishCaught` | dict: ключ `(O)128` **или** `128`, значение `<ArrayOfInt><int>N</int>` |
| Археология | `player > archaeologyFound` | dict, `ArrayOfInt` |
| Минералы | `player > mineralsFound` | dict, `<int>` |
| Отправка | `player > basicShipped` | dict, `<int>` |
| Готовка (факт) | `player > recipesCooked` | dict, ключ = **ID блюда** (не имя рецепта) |
| Готовка (изучено) | `player > cookingRecipes` | dict, ключ = имя рецепта |
| Крафт | `player > craftingRecipes` | dict, ключ = **имя рецепта**, значение = сколько раз крафтили |
| Дружба | `player > friendshipData > item > value > Friendship` | `Points, GiftsToday, GiftsThisWeek, TalkedToToday, Status`; сердца = `Points // 250`, максимум 10 (14 у супруга) |
| Музей | `locations > GameLocation[xsi:type='LibraryMuseum'] > museumPieces` | dict: значение = ID предмета |
| Бандлы | `locations > GameLocation[xsi:type='CommunityCenter'] > bundles` | dict: ключ = int (слот бандла 0..36), значение = `ArrayOfBoolean` (true = предмет сдан) |
| Комнаты CC | там же `> areasComplete` | список boolean |
| Орехи | `goldenWalnutsFound` (поиск по документу) | число |

Правила подсчёта, которые уже реализованы и должны сохраниться:

* **Музей**: `donated` = ID есть в `museumPieces`; `found` = ID есть в `archaeologyFound` (артефакты)
  или `mineralsFound` (минералы). Универсум: 42 артефакта (`Type == "Arch"`) + 53 минерала
  (`Type == "Minerals"`) = **95**. Отдельно считается `museum_found`.
* **Рыба**: универсум = ключи `Data/Fish.json` = **74**. Мусор (`Trash`, `Driftwood`, `Soggy Newspaper`,
  `Broken Glasses`, `Broken CD`, `Joja Cola` — ID 167–172) и желе 1.6 в коллекцию не входят.
* **Отправка**: список 155 предметов (`data/shipping.json`), см. §10 про происхождение.
* **Готовка**: `recipesCooked[output_id] > 0`, `output_id` берётся из `Data/CookingRecipes.json` (поле 2).
* **Крафт**: `craftingRecipes[имя_рецепта] > 0`, всего 150.
* **Бандл готов**, когда `true`-флагов ≥ `need_count` (в `Data/Bundles.json` поле 4; у «любых N из M»
  оно меньше числа предметов).

Ссылка-эталон, по которой сверялись селекторы (MIT): <https://github.com/MouseyPounds/stardew-checkup>
(`stardew-checkup.js`). Если поле не находится — сначала смотри туда, а не в догадки.

## 7. Жёсткие ограничения и запреты

1. **Никаких внешних зависимостей** в рантайме (`tracker.py`): только stdlib. Тесты — тоже stdlib.
2. Интерфейс использует пиксельные игровые иконки из локальных атласов `assets/sprites/` (исключение к первоначальному запрету на ассеты, принятое по уточнению заказчика); не добавлять музыку, звуки или шрифты игры. Документировать происхождение и правообладателя в README.
3. **Никаких сетевых вызовов** из приложения. Телеметрии нет.
4. **Не ломать обратную совместимость**: CLI-команды (`serve|build|info|open`, `--save`, `--saves-dir`,
   `--port`, `--no-open`, `--no-watch`), формат `goals.json`, ключи состояния из §4.
5. **Windows-дружелюбность**: пути с кириллицей и пробелами, запуск двойным кликом по `.bat`,
   кодировка UTF-8 (`chcp 65001` уже в батниках), никаких символов, ломающих `cmd.exe`.
6. **Python 3.9+**. Не использовать синтаксис 3.10+ (`match`, `X | Y` вне аннотаций с `from __future__`).
7. **Приватность пользовательских данных**: `goals.json`, `report.html`, `saves/` — в `.gitignore`.
8. UI: русский первым языком, английский переключателем; никаких «красивых» внешних CDN (шрифты/иконки).

## 10. Приложение: справка

**CLI**

```
python tracker.py serve [--port 8777] [--save ПУТЬ | --saves-dir ПУТЬ] [--no-open] [--no-watch]
python tracker.py build [--save ПУТЬ | --saves-dir ПУТЬ]     # -> report.html
python tracker.py info  [--save ПУТЬ | --saves-dir ПУТЬ]     # диагностика
python tracker.py open                                        # build + открыть в браузере
```

**HTTP API**

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | дашборд (HTML со встроенным состоянием) |
| GET | `/api/state` | JSON состояния |
| GET | `/api/refresh` | принудительно перечитать сейв |
| POST | `/api/goals` | `{"goals":[...],"tasks":[...],"annotations":{...}}` → `goals.json` (старые клиенты без `annotations` поддерживаются) |
| GET | `/api/goals/export` | Экспорт целей, задач, пометок и заметок |
| GET | `/api/saves` | Перечень доступных сохранений |

**`goals.json`**

```json
{
  "goals": [{"id":"a1","title":"Сдать 60 в музей","metric":"museum","target":60}],
  "tasks": [{"id":"t1","title":"Купить 10 клубники","done":false}],
  "annotations": {"fish:128": {"marked":true,"note":"Ловится летом с 12:00 до 16:00"}}
}
```

Метрики: `museum`, `museum_found`, `fish`, `shipped`, `cooking`, `crafting`, `hearts`, `money`.

**Где искать сейвы (порядок автопоиска):** `%APPDATA%\StardewValley\Saves`,
`~/.config/StardewValley/Saves`, macOS Application Support, Proton-путь с `compatdata/413150`,
плюс `./saves` рядом со скриптом. Берётся самый свежий по mtime; несколько — через `--save`.

**Подводные камни, на которых уже наступали:**

* Ключи словарей в 1.6 бывают `(O)128`, в 1.5 — `128` → всегда нормализовать (`norm_id`).
* `recipesCooked` ключуется **ID блюда**, а `cookingRecipes`/`craftingRecipes` — **именем рецепта**.
  Не путать: названия рецепта и результата иногда различаются (`Cookies` vs `Cookie`).
* У локаций Ginger Island в `Data/Locations.json` нет `DisplayName` → нужен словарь `LOC_NAMES`;
  крабовые ловушки и рыба шахт вообще не встречаются в списках локаций → `FISH_FALLBACK_LOC`.
* `Data/Locations.json > Fish > ItemId` может быть с префиксом `(O)`.
* Игра пишет сейв **только в конце игрового дня / при выходе** — «мгновенного live» без мода не бывает,
  и это нормально; не пытайся читать память процесса.
* `2000`/`2600` в игровом времени — это часы после полуночи; окна ловли могут пересекать полночь.
* Порог «файл похож на сейв» — не только размер, но и наличие `<SaveGame` в первой строке.
